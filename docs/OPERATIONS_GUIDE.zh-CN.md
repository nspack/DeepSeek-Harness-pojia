# 作战台：从零开始的详细操作指南

> 面向第一次使用 `wxcvm/dsh-purge`「作战台」的人。这里先教你**识别页面、建立项目、整理本机/授权测试记录、核对结果与导出报告**；不需要先学复杂命令。实际资产探测和其他主动测试只在自有系统或明确许可的范围、时段内进行。

![作战台界面](preview/dock-drill.png)

## 一、先看这四句话

1. **清洗台**负责宿主补丁、提示词和规则；**作战台**负责项目（界面中叫「靶标」）、资产记录、任务状态、证据与报告。它们不是一个开关。
2. **作战台的「创建靶标」是创建本地项目记录**，不是开始扫描，也不会自动发现任何资产。
3. **点击概览、资产、漏洞、报告等页签，只是在查看/管理已存记录**。如果没有数据，看到 0 是正常的；不要把 0 当作网络没有问题。
4. **AI 说“已发现/已修复/已得分”不代表事实已验证**；以落库记录、证据和真实检验结果为准。

## 顶部导航与 ARTEX 本机联动

顶部导航的 **作战 / 资源 / 管理** 是可点击的板块入口；点击后进入各板块首页。对应子页签可以直接打开：作战（概览、资产、漏洞、攻击链、得分）、资源（入口、情报、ARTEX）、管理（指南、环境、技能库、智能体、报告）。横向空间不足时导航栏可以左右滚动。

**ARTEX 已从清洗台迁到作战台 → 资源 → ARTEX**。页面会显示本机 ARTEX 服务是否确认在线、身份不明或仅工具已安装，显示已发现的工具路径和 DSH 实际采用的路径，并允许重新检测。没有创建靶标时也可以打开该页，因为本机工具属于环境资源，不归某个靶标。工具路径存在不等于已通过执行验证；本功能不读取 ARTEX 的账号、数据库或任务，不自动启动工具。

如果尚未建立靶标，切换入口、情报或报告等项目级页面，会出现明确的当前页标题和创建项目提示；需要先创建或选中靶标，才会出现对应记录。

## 二、首次打开（跟着做）

1. 先在 [清洗台指南](./CLEANING_GUIDE.zh-CN.md) 中确认插件安装到正确的 Web/desktop 宿主；两端是分别安装的。
2. 在宿主会话标题附近点击 **dsh-purge**，切到 **作战台**。
3. 第一次进入可能出现 **授权确认**：阅读并按界面完成确认；清洗台不需要这个步骤。
4. 作战台顶部有**靶标下拉菜单**、**归档靶标**、**刷新**和（非嵌入模式下的）**全面浏览**。先不要删除任何东西。
5. 如果显示「还没有靶标」，输入一个**本地项目名称**（例如「我的示例测试项目」），点击 **创建靶标**。这一步只建立数据空间。
6. 选择刚创建的项目，点 **刷新**，回到 **概览**。没有导入记录时，资产/漏洞数量为 0 是预期结果。

### 顶部四个控制如何用？

| 控件 | 功能 | 初学者注意 |
| --- | --- | --- |
| 靶标下拉框 | 在已创建的项目之间切换 | 切换前确认当前项目名称，避免把记录写到另一项目 |
| **归档靶标** | 从当前名册移走整个项目工作区，保存在数据根目录的 `archive/` 中 | 有确认弹窗；资产、证据、报告并未销毁。可在「管理 → 指南 → 已归档靶标」查看、恢复；恢复拒绝覆盖现有同名项目 |
| **刷新** | 重新读取名册、统计与当前页数据 | 只刷新数据，不等于启动任务 |
| **最大化 / 还原** | 在当前宿主内扩大或恢复插件窗口 | 不需要弹出浏览器；清洗台和作战台共用此窗口 |

## 三、导航地图：11 个页签分别做什么

当前界面按 **作战 / 资源 / 管理** 分组：

| 分组 | 页签 | 主要用途 | 新手先做什么 |
| --- | --- | --- | --- |
| 作战 | **概览** | 项目总体数量、任务与异常摘要 | 先看项目是不是选对了 |
| 作战 | **资产** | IP、域名、C 段、服务、端口、指纹及测试状态 | 先看列表与筛选，不急着主动测试 |
| 作战 | **漏洞** | 漏洞记录、等级、状态、证据关联 | 学会区分候选、确认、误报、已修复 |
| 作战 | **攻击链** | 按阶段查看已记录的动作和结果 | 用作记录复盘，确认每步有证据 |
| 作战 | **得分** | 项目得分规则、已登记的得分/证据 | 不把“候选”误算成已得分 |
| 资源 | **入口** | 已记录的会话、连通情况与相关资源 | 仅查看自己有权管理的入口记录 |
| 资源 | **情报** | 已收集的情报和关联信息 | 记录来源，先做阅读与核对 |
| 管理 | **环境** | 操作系统、可执行工具路径、模板和可选资源 | 先看检测结果，只配当前任务必需的工具 |
| 管理 | **技能库** | 查看红队与官方技能、正文可读性、宿主注册情况 | 先刷新，区分“文件可读”和“宿主已列出”；按缺项配置工具 |
| 管理 | **智能体** | 每主会话运行/未知状态、并发上限、角色提示词 | 先刷新状态；不用先修改角色稿 |
| 管理 | **报告** | 查看可交付记录、生成/复制/下载 Markdown | 先确认项目和证据再导出 |
| 管理 | **指南** | 内置五步说明、本机体检、可在当前窗口展开完整中文文档 | **新手建议第一站** |

**备注：**「技能库」已恢复为可打开的页签。正文可读不等于宿主已注册；“宿主已列出”也不保证工具、凭据及运行环境就绪。以页面中的宿主注册状态和实际调用结果为准。

## 四、做一次“零主动测试”的上手演练

下面只是练习**本地项目和记录工作流**，不会向任何目标发送网络探测数据。

1. 在作战台创建 **「我的示例测试项目」**。
2. 打开 **概览**：确认当前项目名称，先熟悉统计卡片。
3. 打开 **资产**：切换「全部 C 段」，看搜索框和筛选项。没有记录时保持空列表即可。
4. 打开 **环境**：点击 **刷新**，看看显示的是 Windows、Linux 还是 Kali，记录「就绪 / 待配置」和工具统计。此时**不需要填写 FOFA、VPS 等可选字段**。
5. 打开 **智能体**：观察「单会话上限」「在跑」「剩余未知」及「各主会话状态」。不要因总数为 0 就推断所有会话都空闲；状态未知时以未知为准。
6. 打开 **报告**：没有实际记录或符合条件的结果时，报告可能为空或提示缺少证据。这说明项目还没有可交付的数据，并非一定是故障。
7. 打开 **指南**，点 **检查技能与宿主注册**，看哪些技能正文可读、哪些已列入宿主、哪些仍有环境缺项。需要完整的平台工具检查时，在 AI 会话中调用 `redteam_preflight`；两项检查都不会主动扫描外部目标。

完成以上步骤，就已经学会最常用的**创建→查看→核对→报告**路径。

## 五、环境页：路径怎么填？

「环境」页不要求你把所有工具装齐才可以阅读数据库、做整理或看报告。不同操作依赖不同能力。

1. 打开 **管理 → 环境**，点击 **刷新**。
2. 看顶部的系统判断（Windows / Linux/Kali）、配置状态、已发现工具数。**配置可继续不等于全部工具已经运行验证**。
3. 你的工具已经集中放在某个目录时，可在 **整包文件夹** 区域填入实际目录，点 **自动分配**，让界面尝试识别文件；确认后再保存。
4. 工具分散时，在各工具输入框填入对应**可执行文件的实际路径**；留空表示采用默认查找逻辑。
5. 模板目录、`FOFA_KEY`、`REDTEAM_VPS_HOST` 和 `REDTEAM_VPS_KEY` 是依任务使用的字段。只做本地记录整理时可以不填；不要把 API Key 或私钥写进截图或工单。
6. 工具按侦察、扫描、Web、内网、隧道、身份权限分类；可搜索并查看来源。Nmap、Nuclei、httpx、naabu、katana 等已配置版本参数的工具可点击 **验证版本**：仅在点击时执行当前已解析路径上的版本命令，失败不修改配置，也不会自动测试靶标。
7. DSH 环境目录现包含 naabu、katana，并可复用本机 ARTEX 管理的七种共享工具路径；**找到路径 ≠ 验证版本成功 ≠ 当前任务能完成**。若不在预置 17 种中，可在下方「自定义工具」添加名称与可执行路径，保存后统一展示；此类工具只检查路径存在，不自动运行。
8. 修改完成点 **保存**，观察成功消息，再点 **刷新**核对配置是否仍在。
7. 若提示环境未就绪，检查**当前要做的工作**真正缺了什么；不要把每个可选项目都当成必需。

**Windows 小提示：** 本机可执行程序可能是 `.exe`，Kali/Linux 下的程序、shell 脚本及路径不能直接当成 Windows 可执行程序。路径必须对应正在运行 DSH 的那一台机器/虚拟机，不能直接填另一设备的本地路径。

## 六、智能体页：不懂代码也能看懂

- **并发上限**：每个主会话的执行智能体限额设置；不是所有主会话共同扣同一个「全局余额」。
- **在跑 N**：根据可获取的宿主活动记录统计；不等同于本机有 N 个系统进程。
- **剩余未知**：有子会话活动缺失、注册表不可用或多个主会话要分开算；**未知不是 0，更不是空闲**。
- **各主会话状态**：展开核对每个会话的已知占用、剩余名额以及错误原因。
- **角色提示词**：用于查看每个角色对应的说明。创建了项目后可按项目保存修改；不懂时保留默认值。
- **恢复默认**：只在确实需要撤销自定义改动时用。保存/恢复动作会影响后续使用的提示词，不是刷新按钮。

如果你只想做项目整理，**完全可以暂时不调整并发数量，也不启动任何智能体**。

## 七、资产与漏洞：先学会看数据

### 资产

1. 在 **资产** 页选择 **全部 C 段** 或一个已存在的分组。
2. 在搜索框输入已有资产的 IP、域名或指纹片段，然后按 Enter / 点击 **搜索**。
3. 按服务、端口、来源、测试状态等条件过滤；看不到条目时先清空筛选。
4. 点击现有条目展开详情，核对 IP、来源、记录时间和关联证据。
5. 「当前测试」是数据库中标记为正在测试的记录/进度视图，**点击它并不会自动开始测试**。

### 漏洞

1. 在 **漏洞** 页按标题、CVE、目标或等级筛选。
2. 分清状态：**候选**表示待核验；**已确认**意味着有人做过相应验证；**误报/已修复**是不同的后续结论。
3. 展开已有记录，查看证据、来源、关联文件，避免只根据标题或风险等级做结论。
4. 修改状态前先确认依据；**状态按钮是修改本地记录，不是自动修复远端漏洞**。
5. 不要把「记录很多」等同于「测试覆盖完整」；记录与证据缺失仍需要在报告中说明。

资产页和漏洞页默认每页显示 100 条，底部的「上一页 / 下一页」可查看剩余记录；分页只影响显示，不删除数据。

## 八、攻击链、得分、入口与情报怎么读

- **攻击链：** 看已经记录的阶段、步骤、执行时间和关联证据；链条中断或某步没有结果时如实留空，不能自动推定下一步成功。
- **得分：** 这里反映项目中已经配置和登记的得分规则与对应证据；仅“疑似有权限”不应被口头算作已得分。
- **入口：** 展示保存在项目中的连接/会话信息；状态提示应依实际的宿主检测结果，不要把保存了地址当成连接成功。代理与 WebShell 的具体工具类型不决定是否可用；`entry_kind` 只用于说明目标侧边界证据，不能代替连通性检查。
- **情报：** 整理来源、时间和关联目标；先阅读和核对来源，避免把过期情报当作实时事实。

在没有授权测试记录时，这几页可以保持为空。**为熟悉界面不需要伪造漏洞、凭据或得分。**

## 九、报告页：怎样导出并检查内容

1. 确认顶部选中的是正确项目。
2. 点 **管理 → 报告**，等待后台读取项目得分报告。
3. 查看已列出的阶段、得分、目标和证据。可点开「复现步骤」观察该条记录是否有对应的动作说明与结果。
4. 如果提示「复现材料待补」，说明相关条目缺少足以支撑的记录，先修正项目中的记录再交付。
5. 通过页面现有的 **复制** 或 **下载 Markdown** 控件导出；复制按钮如果提示失败，说明浏览器剪贴板没有成功写入，不要直接宣称复制成功。
6. 打开下载的 `.md` 文件，确认项目名称、统计、证据是否符合预期；分享前处理任何不宜公开的凭据、内部地址或个人数据。

**报告是数据库记录的呈现，不是自动为结果背书。**

### 命令行可选分享版（不改变原始导出）

默认报告仍保留原文和证据。需要给外部人员查看时，可以在发布包根目录运行：

```powershell
node scripts/export-engagement-report.mjs --engagement <项目ID> --out .\reports --shareable
```

`--shareable` 会对**常见**凭据头、密码/token 字段和 IPv4 做基础掩码，隐藏目标标题与 manifest 中的 engagement ID，并省略原始截图文件。它不会修改工作区数据库或已有完整报告。**这不是完整匿名化保证**：其他个人信息、IPv6、域名、自由文本和嵌入链接仍可能包含敏感内容，分享前必须人工审阅。UI 中的「下载 Markdown」仍为原始报告，不会自动应用此选项。

## 十、Skill、SQLite 与 CLI 诊断

这批次仓库新增了只读命令（需要运行**包含该功能的新版本代码**）：

```powershell
dsh-purge --runtime-status
```

它能检查 Node.js 的 `node:sqlite` 能力、随包 Skill 元数据、复制文件与红队预设路径。**它不会自动安装工具或证明 Skill 已被宿主加载。**

- `sqliteAvailable: false`：当前运行的 Node 无法使用 `node:sqlite`。**完整的红队 SQLite 资产库需要 Node 22.13+（推荐 24）**；Node 18/20 不含该内建模块。`package.json` 的 `>=18` 是整个插件原有安装声明，不保证每项红队功能可用；本次不更改全插件最低版本或额外添加兼容门禁。
- `skills.filesReady: false`：表示技能目录、预设路径或文件内容尚未满足诊断条件；查看 `missing`、`different`、`invalid`。
- `hostInvocable: null`：是正常的「未检测宿主」结果，不表示可用，也不表示不可用。
- 要确认模型真的能使用 Skill，需在**实际运行中的 DSH 宿主原生 Skill 列表**或对应功能中查证；不要把文件显示出来当成可调用。

## 十一、常见故障对照表

| 现象 | 先看哪里 | 常见处理 |
| --- | --- | --- |
| 作战台打不开 | 插件是否装在当前 Web/desktop profile；本机 SQLite 是否可用 | 查看清洗安装状态和 `--runtime-status` |
| 提示「未授权」 | 首次作战台确认是否已完成 | 阅读界面说明并按流程确认 |
| 项目列表是空的 | 是否还没有创建靶标 | 创建一个本地项目即可 |
| 切换项目后数据「丢了」 | 顶部当前项目选的是不是别的项目 | 切换回原项目，再刷新 |
| 资产、漏洞、报告都是 0 | 是否本来就没有录入数据，或当前筛选过滤了全部 | 先清空筛选并核对项目 |
| 环境提示「待配置」 | 此次任务是否需要对应工具 | 只配置本轮必需的路径，保存后刷新 |
| 智能体显示「剩余未知」 | 宿主是否返回完整子会话状态 | 查看每主会话状态与错误；别把未知当空闲 |
| Skill 正文可读但模型找不到 | 磁盘文件与宿主注册表是两回事 | 核对 DSH 当前 scope 的原生 Skill 列表 |
| 窗口太小或无法滚动 | 使用窗口顶部「最大化」；清洗台和作战台正文均有独立滚动区域 | 不再依赖浏览器弹窗 |
| 报告为空或没有证据 | 数据未建立 / 阶段条件未满足 / 记录关联不足 | 先核对记录与实际证据，不要用假数据填充 |

## 十二、我建议的新手使用顺序

- [ ] 能从 **清洗 → 作战台** 正确切换。
- [ ] 读完首次授权确认，理解自己的测试范围。
- [ ] 创建一个**不涉及真实测试**的本地示例项目。
- [ ] 会用顶部项目切换、刷新和最大化/还原。
- [ ] 会看 **概览、资产、漏洞** 页，不把 0 当成自动评估结果。
- [ ] 会在 **环境** 页识别必要与可选字段。
- [ ] 看懂 **智能体** 的“空闲/在跑/未知”区别。
- [ ] 能在 **报告** 页查看缺失证据提示。
- [ ] 知道从哪里打开 **指南**、如何做一次本机体检。
- [ ] 不会误点 **归档靶标**。

## 同版本号但作战台仍是旧界面？

本仓库的 `package.json` 版本号不保证每次源码提交都递增。因此本地仓库与远程 `master` 一致、界面上也显示相同版本号，并不能证明 **DSH 正在加载的插件副本** 已更新。

在作战台顶部点击 **检查更新**，新版会另外比较“实际插件目录”中的 `client.js` 和红队 UI 源文件与 GitHub `master` 的 Git blob；“不一致”只说明文件内容不同，既不能直接判断旧或新，也不代表应覆盖个人修改。先确认弹窗里的实际插件目录，按当前安装方式更新该副本，再**彻底重启 DSH**。仅更新独立 Git 工作区、仅刷新浏览器，都不一定会更新运行中的插件。

如果“源码状态未知”，先确认 GitHub 可达、当前宿主插件确实可访问，然后查看实际插件目录。工作区的 `git status` 只说明该工作区本身，不代表宿主安装路径。


## Desktop 固定版本更新与验收

本维护 fork 的随包脚本为 `scripts/update-desktop-fork.ps1`。先完全退出 DSH Desktop（包括托盘进程），然后在发布包根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\update-desktop-fork.ps1 -DshHome "$env:USERPROFILE\.dsh"
```

如果实际 DSH_HOME 在其他目录，要按实际路径修改；不要把独立 Git 工作区当作正在加载的插件目录。安装完成后完全重开 Desktop，再通过「管理 → 指南 → 运行中插件源码」检查实际目录、版本和差异，进入「技能库」「已归档靶标」核对界面。可用 `-CheckOnly` 做只读版本及入口文件检查。自动化 Windows 运行器只能验证脚本逻辑，不能替代真实桌面加载验收。
