# 清洗台：从零开始的详细操作指南

> 现可在插件「清洗台」中直接展开本文，不必跳转浏览器。若应用显示未完成，请查看返回的具体失败项（补丁、当前宿主写入或 Hook 恢复）；进度达到最后一阶段不等于成功。


> 适用：`wxcvm/dsh-purge` 的「清洗」页。按当前代码中的按钮与状态编写；桌面客户端与 `dsh web` 的安装和运行环境是**两份**。文中「清洗」指本插件在本机 DSH 环境的补丁及提示词/规则管理，不代表验证任何模型行为或安全测试结果。

![清洗台界面](preview/dock-clean.png)

## 一、第一次打开：先认识页面

1. 启动你实际使用的 DeepSeek Harness（官方桌面 EXE，或命令行启动的 `dsh web`）。
2. 点击会话标题附近的 **dsh-purge** 按钮，打开右侧栏。
3. 选择 **清洗**。这里不需要先进入作战台。
4. 确认当前宿主显示为你正在用的版本/路径。桌面版和 Web 版分别装、分别应用；**在 Web 中点击应用，不等于修改了桌面版**。
5. 首次弹出的「用户须知」阅读后按界面确认。

### 屏幕上各区块是什么？

| 界面区块 | 作用 | 新手要做什么 |
| --- | --- | --- |
| 当前版本 / 正式版 / 测试版 | 显示安装版本、检查更新、切换发布分支 | 第一次建议先看，不急着升级或切换 |
| 补丁状态汇总 | 已写入数、待处理/没对上/跳过、shim、备份 | 先判断是否找到当前宿主 |
| 「清洗流程」进度 | 显示家目录→宿主→提示词→补丁→启动器等步骤 | 操作期间看是否完成或报错 |
| 补丁分组与搜索 | 按名称、编号、状态查找补丁，查看完整诊断 | 优先看「需关注」，复制诊断再排查；正常「跳过」无需强行处理 |
| 「提示词注入总开关」 | 开/关插件注入文本 | 仅影响提示词注入，不会删除补丁或关闭作战台 |
| 「应用 / 还原 / 卸载」 | 写入补丁、恢复、移除插件 | 新手先区分这三个按钮 |
| 「提示词」编辑框 | 本机的 `prompt-inject.md` 内容 | 没有主动修改时**不用按保存** |
| 「规则集」 | 管理多份 `AGENTS.md` / `CLAUDE.md` | 先弄懂当前规则，再做修改 |

## 二、只做一次：最简单的首次使用

**先确认插件已经安装。** 如果还没有 dsh-purge 按钮，请先按 [仓库安装说明](../README.zh-CN.md#安装) 安装到当前宿主对应 profile，再完全退出并重开。

1. 打开 **清洗**，等待本机状态加载；若提示「未定位到当前宿主」，先看本文第七节。
2. 查看「提示词」框是否已有默认内容。**不修改正文就直接往下走，不必点保存。**
3. 点击 **应用**。该操作会修改当前宿主安装文件，界面会显示处理进度；不要在处理中反复点击。
4. 看到完成消息后按界面提示重启。桌面 EXE 可能自动结束/重新打开；Web 端会重启相关进程或需要你重新进入。
5. 重启后回到清洗页，查看已写入数量、未匹配/跳过项。**「跳过」不一定是错误**：对应组件可能没有安装，或这一版本不需要它。
6. 新开一轮普通对话做最简单的 UI/功能检查；这只用于确认客户端可正常使用，不表示任何特定模型输出会符合预期。

**操作成功的判据：** 当前宿主路径正确、应用流程完成、重启能打开、补丁状态能再次读取。不能只凭进度条达到 100% 就判断所有补丁均已生效。

## 2.1 查找异常补丁与复制诊断（清洗台增强）

清洗页的补丁列表上方现在有搜索框和状态筛选器：

- **搜索**：输入补丁编号（如 `#12`）、补丁名称或分组，符合的分组会自动展开；清空即可恢复完整目录。
- **需关注**：集中展示「待应用」和「没对上」的项目，便于定位真正需要检查的差异。
- **跳过**：单独查看缺失的可选组件或当前版本不适用的项目；**跳过不等于失败**，不应该为凑满应用计数强行写入。
- **查看诊断**：直接在页内展开宿主类型、路径、补丁状态、shim、备份和最近清洗流程结果。
- **复制完整诊断**：复制所有补丁项及最近的错误信息，便于在 Issue 或对话中排查。它**包含本机的宿主路径与 DSH_HOME**，对外公开前请自行检查或隐藏私人路径；不会复制提示词正文。
- **合并补丁的子项状态**：某一行可能包含多个补丁编号（如 `#45/#46`），即使汇总显示「已应用」，其中某个子项也可能缺失。只要子项状态不一致，清洗台会在该行直接显示各编号的状态；完整诊断中会列出每个子编号的原始状态，方便核对，而不把缺失项默认为成功。
- **重新检测**：仅重新读取当前宿主的补丁状态，不写入补丁、不会保存或覆盖正在编辑的提示词。检测后显示与点击前相比发生变化的项目（含“新增列出/不再列出”）。没有变化也会明确提示；读取失败时保留原状态并显示错误。
- **复制当前筛选**：只复制搜索和筛选命中的补丁诊断，便于专注排查异常；与“复制完整诊断”相互独立，随时可以恢复显示所有补丁。
- **宿主定位与封装线索**：诊断会显示状态接口返回的定位失败原因、Desktop EXE 路径、以及 `app.asar` 未解包标志。诊断仍含本机路径，分享前留意。
- 如果剪贴板被 Desktop 内核拒绝，页面会展开诊断原文供手动选择复制，不会误报复制成功。

正在应用、还原或卸载时，若宿主给出了具体阶段详情或错误，清洗流程下方会直接显示原文。流程中的「已完成步骤」仅表示经过的阶段，不代表所有补丁都成功。

## 2.2 ARTEX 本机联动（安装了 ARTEX 时）

清洗页会自动检测本机 ARTEX 服务的固定健康接口 \`http://127.0.0.1:8787/api/health\`：只有服务返回 \`ok: true\` 且 \`service: "artex"\` 才显示“已连接”，不会因为 8787 端口被其他程序占用就误判。

- **服务状态**：显示是否正在运行、ARTEX 报告的版本，以及跳转至本机 ARTEX 的入口（服务在线时）。
- **工具复用**：发现 \`ARTEX_TOOL_DIRS\` 指定的目录或 Windows \`%LOCALAPPDATA%\ARTEX\tools\` 的 nuclei、httpx、subfinder、ffuf、dnsx 等工具时，dsh-purge 在自己的配置、工具箱、额外目录、PATH 都未找到对应工具后，才自动使用该本机路径；不用复制可执行文件或维护第二份工具配置。
- **环境提示**：显示能定位到的 ARTEX 工具与共享路径，以及通过 \`ARTEX_SKILL_DIR\` 环境变量明确指定的 Skill 目录（只显示，不自动复制技能）。
- **未运行也可复用工具**：ARTEX Desktop 退出时，已有的本机工具文件不一定被删除；只要路径还存在，dsh-purge 仍可使用。Docker 容器里的工具不会自动当作 Windows 可执行文件。
- **手动重新检测**：ARTEX 启动、退出或安装工具之后，可以点击清洗台的「重新检测 ARTEX」，刷新当前状态。

**不会**自动启动 ARTEX、执行扫描、读取或复制 ARTEX 密钥、数据库、任务及登录信息，也不会覆盖两个项目的配置文件。检查成功不等于 ARTEX 的任务、Skill/MCP 已经连接到 DSH 模型；这部分需要另行验证授权和接口。ARTEX 不存在时清洗台其余功能不受影响。

## 三、应用、还原、卸载：到底有什么区别？

| 按钮 | 会怎样 | 什么时候用 |
| --- | --- | --- |
| **应用** | 对**当前宿主**执行清洗/补丁写入，必要时提示重启 | 初装后，或插件/宿主升级后需要重新应用 |
| **还原** | 尝试从本机备份恢复被修改过的文件；保留插件及用户文件 | 希望让该宿主恢复原有代码时 |
| **卸载** | 先尝试恢复补丁，再移除插件配置及相关文件 | 不再使用插件时 |
| **保存提示词** | 把当前编辑框内容写回文件 | **只有真的改了文本才用** |
| **恢复默认提示词** | 把编辑框恢复为插件内置默认内容 | 想撤销手工编辑时；确认后可能覆盖自己的定制 |

**特别注意：** 「还原」不是「卸载」，「关闭注入」也不是「还原」。如果改过的内容很重要，先自行留存。卸载界面有二次确认，别把它当刷新按钮。

## 四、怎样看懂补丁状态

- **已应用 / 已写入**：当前检查识别为相应写入结果。
- **待应用 / 待处理**：当前文件中仍可检测到原始匹配内容；需结合当前宿主版本判断。
- **没对上 / 未匹配**：预期代码特征在该版本中没有找到，不应直接当作已经应用。
- **跳过**：此版本无需该项、对应包缺失或该项不适用于当前环境。
- **有备份 / 无备份**：显示恢复文件可用性；没有备份不要假定「还原」一定能恢复所有项目。
- **shim cmd / ps1 / unix**：对应不同平台的命令启动器；某些项目显示「本端不需要」是正常的。

遇到异常，先记下**补丁名称、状态、当前宿主版本和错误原文**，再处理；不用一次把所有补丁都手动折腾一遍。

## 五、提示词和规则集：新手怎么操作

### 5.1 提示词编辑框

1. 找到页面下方 **提示词**。
2. 没有特殊需求时，保留当前默认文本，**不要为了“激活”它多点一次保存**。
3. 要改自己写的项目说明时，先复制原文留底，再编辑，点击 **保存提示词**。
4. 「恢复默认」会放弃当前自定义文本；使用前确认自己不再需要它。
5. **提示词注入总开关**用于单独停止/恢复插件的文本注入；它不移除补丁、不停用作战台，也不会清空你的规则集。界面说明指出开关对下一条消息生效。

### 5.2 规则集（`AGENTS.md` / `CLAUDE.md`）

1. 打开 **规则集**，先看已存在的项目与当前启用项。
2. 点选一项进入编辑器，核对其名称、目标文件和正文。
3. 新建时填写唯一 ID、显示名，选择 `AGENTS.md` 或 `CLAUDE.md`，填写内容后保存。
4. 启用某个规则时，留意界面反馈。规则集与提示词文件不是同一个东西。
5. **删除**从规则列表中移除该项；不确定要不要删就先留着。
6. 使用聊天命令也能管理：`/rules list`、`/rules use <id>`、`/rules create <id>`、`/rules delete <id>`。不熟悉命令时用界面即可。

建议新手先用一份简单的说明做测试，例如“本项目用中文解释代码改动，输出先给结论”，确认保存与启用链路无误后再管理多套规则。

## 六、版本切换和重启

- **正式版 / stable** 与 **测试版 / beta** 是不同发布轨道；切换前先看当前版本与目标版本。
- 更新操作可能安装插件并重启当前宿主，不是单纯的「检查更新」；更新期间页面短暂断开不一定代表失败。
- 旧版本/选定版本可能被固定；若想回到最新版，需按界面更新或取消相应版本选择。
- **升级插件包 ≠ 已重新应用本机补丁。** 升级后根据页面状态判断是否需要再次应用与重启。
- 桌面端要**彻底退出（包括系统托盘）**再启动；Web 端则停掉对应 `dsh web` 进程并重新运行。

如需命令行，只在**实际安装了当前仓库版本**的环境执行：

```powershell
dsh-purge --status
dsh-purge --runtime-status
dsh-purge --help
```

其中 `--runtime-status` 是只读的 Node/SQLite、Skill 安装位置诊断；它不会修改文件，也不能证明宿主已加载 Skill。

## 七、常见问题：照着排查

| 现象 | 优先检查 | 下一步 |
| --- | --- | --- |
| 看不到 dsh-purge 按钮 | 装错了 Web/desktop profile；插件本体未写进 profile | 查 [安装章节](../README.zh-CN.md#安装) 的 bundle/insert 提示，完全退出重开 |
| 提示「未定位到当前宿主」 | 进程、DSH_HOME、实际 EXE 安装目录是否匹配 | 彻底退出当前宿主后重开，再查看；不要猜盘符 |
| 点击应用后页面断开 | 桌面端/服务端可能正在重启 | 看界面重启提示；若长时间未恢复，手动启动正在用的那端并查错误 |
| 部分补丁是「跳过」 | 相关包是否安装 | 若组件本就没有，属于正常情形 |
| 部分补丁是「没对上」 | 宿主升级后文件结构可能变了 | 记录版本与补丁项；不要把未匹配当作成功 |
| 保存提示词后好像没变化 | 当前会话是否仍在用旧配置；注入开关是否暂停 | 先确认保存状态；对下一条消息或重开会话检查 |
| Windows 版本没有变化 | 是否只应用了 Web 端 | 在桌面端独立安装和应用 |
| 作战台为空或不可用 | 清洗不是作战台数据初始化 | 前往 [作战台指南](./OPERATIONS_GUIDE.zh-CN.md) 检查靶标、环境与运行时 |
| 想完全恢复原状 | 还原与卸载不是一个动作 | 先决定是「只还原补丁」还是「移除插件」，看第三节 |

## 八、第一次使用自检

- [ ] 能在正在使用的宿主找到 dsh-purge 按钮。
- [ ] 知道「清洗」与「作战台」是两页，而 Web / desktop 是两个安装目标。
- [ ] 看得懂「已应用 / 待处理 / 没对上 / 跳过」。
- [ ] 没修改提示词时，没有多余地点击保存。
- [ ] 点应用后看了执行结果并完成必要的重启。
- [ ] 知道还原、卸载和注入开关不是一回事。
- [ ] 有异常时能提供宿主版本、所在页面与完整错误文字。
